# 1.什么是AgentRuntime 智能体运行服务

**AgentRuntime Platform** 是一个专为企业级 AI Agent 应用设计的、部署在企业自有云环境下的 PaaS (Platform-as-a-Service) 平台。它专注于解决 Agent 在生产环境中从代码调试、部署到升级全生命周期的核心挑战，提供统一的 **Agent 运行时管理、工具（Tool/MCP）生命周期管理、底层异构资源的精细化弹性调度，以及多级安全隔离能力**。平台负责采集并输出 Agent 运行指标（Metrics）与调用链路（Trace）数据供 AI 可观测产品或开源可观测组件实现可观测或监控能力。

AgentRuntime支持 Python、Node.js、Java 等主流语言的运行时，为Agent应用提供标准化部署、版本管理、灰度发布与弹性实例调度能力。内置 Code Interpreter 与 Browser Use 两类沙箱服务，分别支持安全隔离的代码执行（含文件 I/O 与会话管理）和浏览器自动化任务（如网页浏览、数据抓取、表单填写）。

平台提供统一的工具调用治理能力，兼容MCP协议，支持工具一键接入、自定义发布及凭证集中管理。Agent、沙箱、大模型与工具的访问凭证均通过安全机制统一管控，可与企业凭证中心或AI网关集成。

可观测数据覆盖链路追踪（Trace）、提供用户侧日志采集（Log）与运行时指标（Metrics），平台通过注入探针自动采集 Agent 执行步骤的耗时、状态等运行数据，并支持上报至 AI 可观测产品或对接开源可观测组件，完成后续的监控与可视化分析。

# 2.产品详情

AgentRuntime 智能体运行服务是面向企业级 Agent 应用的一站式运行时 PaaS平台，内置统一执行环境，提供多语言运行时（Python、Node.js、Java）、安全沙箱（Code Interpreter、Browser Use）、模型与工具接入及凭证统一管理，覆盖 Agent 从调试、部署到升级的运行态管理。对外输出运行指标（Metrics）与调用链路（Trace）数据，可观测与监控能力由 AI 可观测产品或开源可观测组件提供。本文主要介绍AgentRuntime的工作原理和核心功能等。

**工作原理**

AgentRuntime采用分层架构设计，由 Agent 运行时、Sandbox 沙箱平台、模型管理中心、工具管理中心、凭证管理中心和可观测模块组成。

- **核心运行层**

  Agent 运行时为各类 Agent 应用提供标准化执行环境，支持零代码和高代码两种开发模式，并实现版本管理、灰度发布与弹性实例调度。

- **模型管理层**

  支持注册管理模型服务，通过AI网关代理实现。

- **工具管理层**

  工具管理中心支持 MCP 协议，提供预置工具与自定义工具接入能力。

- **凭证管理层**

  凭证管理中心统一管理 API Key凭证，并在运行时安全注入。

- **可观测层**

  可观测模块基于 OpenTelemetry 采集从请求入口到模型、工具、外部依赖的全链路 Trace，并以Metrics 形式提供 Agent 执行耗时、状态等运行指标数据，支持上报至 AI 可观测产品或对接Prometheus、Grafana、Jaeger、Loki 等开源可观测组件进行监控与分析。

- **部署**

  各模块通过标准 HTTP API（兼容 OpenAI Chat Completions 协议）与多语言SDK（Python/Node.js）对外提供能力，支持与 LangChain、AgentScope 等主流框架集成。

**核心功能**

- **统一执行环境**：为 Agent 应用提供标准化、稳定、高效的运行环境，确保一致的开发和运行体验。

- **全生命周期管理**：支持 Agent 应用从调试、部署到升级的完整流程管理，并在发布后持续输出运行指标数据。

- **多语言运行时**：内置 Python 3.0+、Node.js、Java 运行时，支持企业利用现有技术栈构建 Agent。

- **安全沙箱能力**：提供 Code Interpreter（代码执行与会话管理）和 Browser Use（网页浏览、数据抓取、表单填写）两类沙箱能力。

- **模型接入**：支持第三方模型、开源托管模型及向量模型接入，集成AI网关提供模型代理、负载均衡、超时控制、内容安全与 Token 限流能力。

- **工具管理**：支持 MCP 协议，提供工具市场，支持预置工具接入与自定义工具发布。

- **凭证管理**：统一管理 Agent、Sandbox、LLM 及工具调用所需的 API Key凭证类型。

- **可观测能力**：通过探针自动采集 Trace 调用链与 Metrics 运行指标，覆盖执行耗时、状态及错误信息等运行数据，可上报至 AI 可观测产品或对接开源可观测组件实现监控与可视化分析。

- **多模式开发**：支持零代码（面向业务人员）和高代码（Python/Node.js/Java 编码）两种开发方式。

AgentRuntime提供统一执行环境、全生命周期管理、多语言运行时、安全沙箱、模型管理、工具管理、凭证管理及运行指标采集能力，支持企业基于自有技术栈开展 Agent 应用运维，并可对接既有可观测与监控体系。

# 3.产品价值

AgentRuntime 智能体运行服务是面向企业级 Agent 应用的一站式运行时 PaaS平台，提供统一的执行环境、全生命周期管理、多语言运行时支持、安全沙箱服务、模型管理、工具生态集成、凭证统一管理及运行指标采集能力。平台支持零代码和高代码两种开发模式，适配Python、Node.js、Java等语言，兼容主流Agent框架，并可通过AI网关集成模型与工具服务。本文主要介绍AgentRuntime的核心产品价值。

**企业级能力，标准化交付**

继承 EDAS 在应用托管与治理领域的技术实践，提供以应用为核心的管理模型。支持基于 CPU/内存及业务指标的弹性伸缩，内置流量治理能力，实现版本灰度发布与流量切分。开发者关注应用、版本、配置等业务概念，无需操作 Kubernetes 底层资源。

**统一的智能体执行与生命周期管理**

为各类Agent应用提供标准化执行环境，支持从调试、部署到升级的完整生命周期管理。内置Python 3.0+、Node.js、Java运行时，适配企业现有技术栈。沙箱环境支持Code Interpreter和Browser Use，满足代码执行与网页自动化需求。

**按需弹性伸缩与多级安全隔离**

支持请求驱动的弹性伸缩，实例可在无流量时缩容至零，在请求到达时快速启动。提供容器隔离、请求级隔离与会话级隔离机制。凭证管理模块统一管控Agent、沙箱、大模型及外部工具的访问凭据，支持动态注入与一键禁用。安全策略通过预定义等级配置，平台自动完成底层资源与调度策略绑定。

**模型与工具的集成化管理**

通过企业AI网关集成通义千问、DeepSeek等主流模型，支持多模型负载均衡与故障降级，提供内容安全审核与Token限流能力。工具管理模块支持MCP协议，提供标准化工具定义、注册与调用接口。第三方工具可通过AI网关接入，实现模型服务与工具能力的统一入口管理。

**可观测与可运维的生产支撑能力**

平台通过探针自动采集基于Trace的Agent决策路径数据，覆盖从前端请求、网关、Agent、模型到工具调用的完整链路，并提供各执行步骤的耗时、状态与响应时间等Metrics运行指标。上述运行数据可上报至AI可观测产品，或通过OTLP标准协议对接Prometheus、Grafana、Jaeger、Loki等开源可观测组件，由客户既有监控体系完成可视化分析与告警。平台同时具备版本管理、灰度发布、Endpoint配置与弹性伸缩策略设置能力，满足企业级应用持续演进与稳定运行需求。

# 5.应用场景

AgentRuntime 智能体运行服务提供统一执行环境、全生命周期管理、安全沙箱及多语言运行时支持，为满足企业级Agent应用在部署与运维阶段的基础需求提供指标数据。本文主要介绍AgentRuntime的应用场景。

**场景1：企业级AI应用全生命周期管理**

AgentRuntime平台支持从调试、部署到升级的完整Agent应用生命周期管理。企业可使用Python、Node.js、Java等语言编写的Agent应用，并通过平台进行统一管理。平台通过探针自动采集调用链路（Trace）以及LLM调用Token消耗、执行耗时、状态等运行指标，可上报至AI可观测产品或对接开源可观测组件，由客户的监控体系完成链路分析与告警。该场景适用于企业内部AI应用团队，需要标准化部署流程、简化运维复杂度并提高开发效率的场景。

**场景2：MCP工具托管与运行环境优化**

AgentRuntime平台为MCP（Model Control Protocol）工具提供标准化的托管运行环境。在百炼平台等场景中，传统方案将多个MCP集中部署在单一ECS虚拟机上，存在环境依赖冲突、安全隔离不足、资源弹性缺失和稳定性差等问题。AgentRuntime通过容器化部署解决环境依赖问题，每个MCP打包为独立容器镜像，包含所需全部环境和依赖；通过多级隔离机制（容器隔离和沙箱隔离）提升安全性；通过按需弹性伸缩实现资源高效利用，无请求时实例可缩减至零；通过故障隔离确保单个MCP故障不影响其他服务。该场景适用于需要托管多个第三方或开源工具的企业平台，特别是对安全性和稳定性有较高要求的场景。

**场景3：安全敏感型Agent应用部署**

针对执行不可信代码的安全风险，AgentRuntime提供多维度安全隔离机制。平台支持物理或集群隔离和请求或会话级隔离等多种模式。管理员可预先定义不同安全等级对应的资源和策略，开发者只需选择相应安全等级即可自动应用对应隔离措施。

**场景4：自动化任务与数据处理**

AgentRuntime支持代码执行和数据处理能力，提供安全隔离的Code Interpreter环境用于执行动态生成的代码，支持文件I/O和会话管理。同时支持浏览器自动化，通过VNC+Playwright实现网页浏览、数据抓取、表单填写等任务。平台还支持桌面应用自动化，通过GUI方式操作本地应用程序。该场景适用于需要自动化数据采集、处理和分析的企业应用，如舆情监控、市场调研、业务流程自动化等场景。

**场景5：跨部门协作的模型与工具共享**

AgentRuntime支持跨部门、跨项目的模型与工具共享机制。凭证管理模块统一存储LLM访问密钥与工具API凭证，按项目或角色分配使用权限。Tool Hub支持自定义工具发布与内部共享，便于沉淀企业级能力资产。多个Sandbox环境可独立配置依赖与镜像，满足不同团队的技术栈差异。开发模式支持从低代码快速验证到高代码工程化落地的平滑过渡。该场景适用于大型集团企业，总部统一建设Agent基础设施，各子公司或事业部基于同一平台开发专属Agent应用，实现能力复用与标准统一。

# 7.使用限制

您在使用AgentRuntime 智能体运行服务时注意不要超过相应的限制值，以免程序出现异常。

| 分类 | 受限说明 |
| --- | --- |
| 集群 | 管控集群和业务集群需分开部署（至少 2 个 K8s 集群），每个集群最低配置 16C32G。管控台需要能访问业务集群的 K8s API Server。业务集群 AI 网关需要有外部可访问的 IP（LoadBalancer 类型 Service）。独占模式下大量并发会话会增加集群资源压力，需根据业务规模规划集群容量。 |
| 沙箱 | 沙箱首次启动受镜像拉取和 Pod 调度影响，启动时间可能较长，建议提前做镜像预热。 |
| 凭证 | 自签名证书环境下部分操作的使用体验可能受影响。 |
| 存储 | OSS Bucket 和镜像仓库需要提前准备并确保有足够的存储配额。OSS 非必需，但如需使用零代码 Agent、沙箱状态持久化或部署加速功能则必须配置。 |
